# Measurement methodology

A manual speed test first measures HTTP application RTT with repeated uncached health requests, then transfers parallel HTTP streams. The client increases 1→2→4→8 streams, displays aggregate throughput samples every 250ms in the live download/upload chart, excludes warm-up, and uses a median stable window rather than a peak for the final result. One Mbps is 1,000,000 bits per second. Directional work is capped at 15 seconds. The separate stability tab uses WebSocket RTT samples one second apart only while visible; jitter is the mean absolute difference between consecutive RTTs from the last 30 samples. Results represent the deployed ingress route; neither HTTP nor WebSocket RTT is ICMP ping.
